## Background

The air-gapped hospital runs Hospital Directory API **v1.1**. HCopilot needs **v1.2** only for one endpoint, `GET /er/current-visits` (the other four v1.2 additions are HCAT-only). We want to install HCopilot before v1.2 exists, without errors or noise. Source: `13. The Hybrid Design Decision.pdf`, section on the API.

Verified live on 2026-09-30 (mocks in `RESTful-API-Integration`): `:6000` (v1.1) answers `/er/current-visits` with `404 {"error":"NOT_FOUND"}`; `:6001` (v1.2) returns the roster. The mock is not the real server, and the real one has already deviated from its contract (500 on POST, garbled Arabic, dotted IDs), so we do not depend on its behaviour for unknown routes.

## Confirmed decisions

1. **No detection of any kind.** Not the vendor's version string (the vendor will name/format versions differently), and not probing the endpoint's reaction. Deterministic instead: an explicit **admin switch**.
2. **Settings → "Live ER roster" switch, default OFF.** While off, nothing calls `/er/current-visits`.
3. **Directory search stays ON** (unchanged), with a quiet, plain fallback message and the existing "Enter details manually" path.
4. **Manual add is unchanged** and becomes the visible primary path while the roster is off.
5. **Enable is gated by a passing test.** The switch only turns on after "Test ER roster" succeeds (server-side check, not just UI). Turning off is always allowed.
6. **Legacy frontend (`frontend/`) is the long-living system** (see the Hybrid Design Decision); it gets full behaviour. `frontend-new/` only gets the minimum so it does not break on the new status.

## Design

- New status `roster_off` in `client.py`'s vocabulary, returned by `get_er_current_visits()` **before any HTTP call** when the switch is off.
- New column `ExternalApiSettings.er_roster_enabled` (Boolean, not null, default false) + Alembic migration. Read fresh from DB each call (same no-cache rule as the rest of `settings_db.py`).
- `client.get_er_current_visits(force=False)`: `force=True` is used only by the test endpoint to bypass the switch.
- `er_sync.reconcile_er_departures()`: `roster_off` → return immediately, debug log only, **never discharges**. Genuine outages (`timeout`, `connection_error`, etc.) keep today's warning + skip behaviour.
- Existing stays that carry an `er_visit_id` are untouched when the switch goes off (no auto-discharge, no edits).
- Upgrade note: existing dev DBs default to OFF, so anyone using the v1.2 mock must flip the switch once.

## Deployment note (air-gapped install)

HCopilot **ships with the Live ER roster switch OFF**. Install and run against directory API v1.1: search and manual add work; the roster panel is hidden and the departure sync does nothing. When 3iSoft deploys `/er/current-visits`: Settings → Hospital Directory API → Live ER roster → **Test ER roster** → switch **On** (the backend refuses to turn it on unless the test passes). Switching it Off is always allowed and takes effect immediately, with no restart. Databases are upgraded by the normal `alembic upgrade head` (migration `a9c3d7e1f2b4`).
